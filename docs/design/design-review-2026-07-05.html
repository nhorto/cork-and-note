The verdict

The Château Label system is genuinely good — a warm, confident identity with an excellent core: charcoal on cream measures 13.2:1, the burgundy CTAs 9.7:1, and the signed-in tab screens are almost entirely token-driven. The problems are not the design; they are drift and unfinished edges. Three patterns account for most of it: (1) the pre-login screens never got the rebrand, (2) gold is being used as ink when it only works as decoration, and (3) the same concept — a chip, a button, a header — has been redrawn slightly differently each time it was needed.

FINDING I — CRITICAL

The app has two brands, and guests see the wrong one

Signed-in screens are unmistakably Château Label. But index.js, login.js, register.js, and forgot-password.js import zero theme tokens. They run on a near-miss red #8C1C13 (not your wine #8B1A1A), flat gray #E7E3E2, Bootstrap grays and Material green in the password checklist, and the old purple #8E2DE2 still paints the very first spinner a user ever sees, plus both forgot-password CTAs. No serif type appears until after login — first impressions never meet the brand.

FINDING II — CRITICAL

Gold is decoration, not ink

The single most repeated readability issue: gold.shimmer captions label nearly every section of every screen at 11px — at 2.45:1. Gold badges put cream text on gold ground. Gold-tinted cards put gold text on gold. None of it clears even the large-text bar.

FINDING III — BUG

The pill that renders square

borderRadius.full doesn't exist in the theme (sm/md/lg/xl/round do). Every chip styled with it resolves to undefined and renders square — in 8 files: varietal chips, flavor tags, wine-type pills, status badges, the star container, photo-count pills, and the wines-tab filter chips. The cellar flow uses .round correctly, so the same chip concept is round in one flow and square in the next.

FINDING V — ACCESSIBILITY

Small targets, silent buttons, frozen type

  • Touch targets: the de-facto icon button is 40×40 (Apple HIG minimum is 44×44); worst offenders are profile back buttons (~34px), place edit/clear (32px), chat photo-remove (18px), and flavor chips (~26px tall). A shared icon-button component with hitSlop fixes this class of issue.
  • Screen readers: of ~30 icon-only touchables, exactly 3 have an accessibilityLabel (tab-bar +, Tonight's Pick collapse, one edit link). Every ×, ‹, ✎, eye-toggle, and stepper is announced as nothing.
  • Dynamic Type: tabBarAllowFontScaling: false, and font sizes are fixed units app-wide; 9–10px text (badges, timestamps, filter counts) sits below the theme's own 11px caption floor. Set an 11px floor and let badges grow.
  • Sliders: the 0–5 rating slider (0.1 steps, 24px thumb) has no accessibilityRole="adjustable", no increment actions, and no tap-to-set fallback.
FINDING VI — PLATFORM

Android is quietly sans-serif

Georgia isn't an Android system font. Five newer components guard it (Platform.OS === 'ios' ? 'Georgia' : 'serif') — the other ~15 files hardcode 'Georgia' and silently fall back to sans on Android, so half the brand's serif voice disappears there. Nobody reads typography.fonts.serif from the theme.

// styles/theme.js — make the theme the single source of serif truth
fonts: {
  serif: Platform.select({ ios: 'Georgia', android: 'serif', default: 'Georgia' }),
  sansSerif: 'System',
}
// then replace every raw fontFamily: 'Georgia' with typography.fonts.serif.
// Longer term: bundle Playfair Display / Lora via expo-font for a true
// cross-platform label face (the theme file already suggests this).
FINDING VII — POLISH

The last 10%: states, motion, and leftovers

  • Error states are the weakest link. Home swallows fetch errors and renders zeros; a cellar fetch failure shows the "Start your cellar" onboarding (actively misleading); sommelier logs failures only to the console. A small inline "Couldn't load — retry" card component, used everywhere, closes this.
  • Motion & haptics: zero. No animations beyond default modal slides; the sommelier "typing" dots and "Thinking…" are static text; HapticTab exists but is imported nowhere. Three cheap wins: animate the typing dots, haptic on the center + button and on save-success, fade-in for Tonight's Pick.
  • Shipped placeholders: "Rate Cork & Note" points at idXXXXXXXXXX; the notifications toggle saves nothing then claims it did; Delete Account says "Feature Coming Soon"; every winery shares one canned About sentence; user@example.com fallback; hardcoded v1.0.0 (×3); the 404 page is the untouched Expo template with its teal link.
  • Dead code to delete: Header.js (broken — contains a pasted copy of _layout.js and the old purple), WineCard.js, ConversationList.js, WinerySearchModal.js, MapErrorBoundary.js, six Expo template components + constants/Colors.ts. Deleting them removes most remaining off-palette hexes in one sweep.
  • Copy: Title Case ("Update Password", "Apply Filters") vs sentence case ("Add a bottle", "Log a wine") split roughly by screen age. The newer sentence case reads better with the serif voice — standardize on it. Also "…" vs "...", "Log In" vs "Sign In".
FINDING VIII — YOUR OWN NOTES, CONFIRMED

Items from "notes from using the app.txt"

  • Overall rating placement — agreed, and it compounds: overall sits above the detailed ratings in WineEntryForm. Tasting flow order should mirror tasting order: identify → detailed impressions → flavors → notes → overall last.
  • Wines-tab filters overflow sideways — confirmed: three horizontally-scrolling chip rows grow unbounded with your data. The cellar's filter sheet (searchable facets, live result count) is the better pattern — reuse it here.
  • Map help button — the first-run hint banner exists but disappears forever once pins exist; a small "?" pill near the search bar could re-summon it.
  • Winery sheet → page — the winery already has a full detail page; the map's pin modal could offer "View winery" as its primary action so the modal stays a shortcut, not a destination.

What works well — keep it

  • The identity itself: burgundy + gold + cream with serif display is distinctive, warm, and appropriate to the subject. Nothing here argues for a rebrand.
  • The signed-in tab screens are ~100% token-driven — home.js has literally zero hardcoded colors.
  • State design where it was attempted is excellent: cellar's example-data onboarding, Tonight's Pick's five-state matrix, the scanners' fail-soft retry flows, register's live password checklist.
  • Ceremonial details — gold hairlines, the line-diamond-line divider, the raised burgundy center tab — give it a crafted feel most apps lack.

Priority roadmap

  1. Retheme the four pre-login screens with existing tokens; kill the purple; wire or hide the social buttons. Biggest visible win per hour. ~½ day
  2. Add gold.text, darken pewter, fix badge inks — clears 9 of 11 failing pairs app-wide via theme edits + caption style. ~½ day
  3. Add full: 999 to borderRadius — one line, fixes chips in 8 files. 5 min
  4. Extract <ScreenHeader> (safe-area, 44px targets, one back icon, labeled) and adopt it on all 14 detail/profile screens. ~1 day
  5. Platform-guard the serif via the theme token; replace raw 'Georgia'. ~2 hrs
  6. Standardize button/chip/label recipes (one primary, one cancel, one chip colorway, gold captions → gold.text, sentence case) and sweep. ~1 day
  7. Error-state card + a11y labels + 11px floor + haptics/typing animation. ~1–2 days
  8. Delete dead components & template leftovers; retheme the 404. ~1 hr

All of it is additive to the current system — nothing above conflicts with the dark-mode direction you have in progress, and the gold.text/pewter tokens give dark mode a cleaner starting point too.
